# ページ構成 類似度調査と改修判断(2026-07)

「どのページも構成がほとんど同じに感じる」という指摘を受け、全137ページのセクション骨格
(ヒーロー型 → 統計 → 交互セクション → グラフ → 表 → CTA帯 …の並び)を機械抽出して
クラスタリングした。本書はその結果と、改修の要否判断・今後のロードマップである。

## 調査方法

- 生成済み全HTMLの `<main>` から構造クラス(HERO_page / HERO_sub / HERO_full / STATS /
  BUY / BLEED / SPLIT / CHARTS / TABLE / FAQ / RAIL / TOC / TIMELINE / PROSE / CTA_BAND)の
  出現順を抽出し、連続重複を圧縮して「骨格シグネチャ」とした
- 同一シグネチャのページをグループ化(スクリプトは本書末尾に記載)

## 調査結果(骨格パターン: 29種 / 完全一致グループ: 13)

| 同一骨格グループ | ページ数 | 骨格 | 判定 |
|---|---|---|---|
| ニュース記事 | 33 | HERO_page → PROSE | **統一が正** — Apple Newsroom等も記事レイアウトは単一。変更不要 |
| 製品ページ(スマホ・タブレット) | 18 | HERO_sub → STATS → BUY → BLEED → SPLIT → CHARTS → FAQ → TABLE → CTA | **要改修** — 旗艦もエントリーも同一の流れで、ラインの性格が構成に出ていない |
| 技術詳細(シリコン・冷却・カメラ) | 18 | HERO_page → TOC → STATS → CHARTS → SPLIT → TABLE | 許容 — ドキュメント型は型の統一に価値がある(Apple技術ページ同様)。中身(図・グラフ・章)は各ページ固有 |
| 仕様(specs)ページ | 18 | HERO_page → TABLE | **統一が正** — 仕様表はフォーマット統一こそが親切。変更不要 |
| 法務・導入事例など文書 | 11 | HERO_page → PROSE | **統一が正** — 規約類は可読性優先。変更不要 |
| アクセサリ製品 | 6 | HERO_sub → STATS → BUY → SPLIT → FAQ | **要改修(軽)** — 冷却・音・電源と性格が違うのに同一構成 |
| 技術ハブ | 6 | HERO_sub → RAIL → CHARTS | 許容 — シリーズ一覧の型統一は回遊性に寄与 |
| OSバージョン | 4 | HERO_sub → STATS → SPLIT → TABLE | 許容 — バージョン比較の見通しを優先。最新版のみ将来リッチ化の余地 |

## 判断: 全面変更は「不要」、ライン別の性格出しは「必要」

同一骨格の大半(80ページ超)は記事・仕様・規約・ドキュメントであり、これらは
**統一されているほど良い**種類のページである(参考にしたApple/REDMAGICも同様の設計)。

体感の単調さの実因は **製品24ページが「ラインの性格」を構成に反映していない**ことにある。
よって改修方針は「テンプレートの全面差し替え」ではなく **「ライン別の固有セクション注入」** とする。

## 今回実施した改修(第1弾)

- **ゲーミング系(SUZAKU / Neo / Pad / Pad Neo)**: 「タイトル別 実測パフォーマンス」表を追加。
  平均fpsと30分後fps(持続性能)を掲載し、冷却の物語と接続
- **スタンダード/エントリー系(TSUBAME / Lite / TSUBAME Pad系)**: 「電池持ちと充電の目安」表を追加。
  動画再生・ブラウジング・ビデオ通話・30分充電の回復量という生活軸の数値
- **アクセサリ6種**: 製品ごとに異なる比較グラフを追加(クーラー=温度低下、Buds=遅延比較、
  充電器=充電時間、ケース=装着時温度上昇、Grip=操作遅延、Dock=ワイヤレス給電出力)
