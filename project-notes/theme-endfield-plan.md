## 0-A. 参考資料メモ(第1弾・ゲーム内スクリーンショット5枚 / 2026-07-18受領)

ユーザー提供のゲーム内UI画像から観察した設計言語(**続きの資料が来る前提の暫定メモ**):

- **基調はチャコール系のダークグレー**(真っ黒ではない #1a1a1a〜#242424 前後)。
  背景に斜めハッチ/走査線/等高線(トポグラフィ)テクスチャを薄く敷く。
  ローディング画面・計算機UIとも「灰色の階調+極細の白枠線」で面を構成。
- **主アクセントはビビッドイエロー**(黄 #f5e100〜#ffe600 前後)。CTAボタン
  (「オペレーター選択」「10回スカウト」「一括受取」)は黄地+黒文字の丸角/角形。
  プログレスバー・DAY数字・選択ハイライトも黄。→ `accent` は黄、
  `accent-contrast` は黒系がほぼ確定(白文字はコントラスト不成立)。
- **白⇄黒のブロック反転**: タブUIは選択側=白地黒文字/非選択側=黒地白文字。
  明部(スタンプ画面・特典画面)は白〜ライトグレーの紙面に黒パネルを置く構成もある。
- **第2アクセントにミント/シアン系**(薄青緑 #bfe8e6〜強めの青緑グロー)。
  スカウト画面の環境光やスタンプ画面の背景に大面積で使用。テーマでは
  `extra_vars`(グラデ・グロー)候補。
- **少量の赤**を警告・記号(▲マーク、レジスタマーク風)に点で使用。多用しない。
- **工業ディテール**: ハザードストライプ、バーコード、型番表記(MK-24 / IPX3-21)、
  CMYKレジストレーション風の小さな色チップ(緑/シアン/橙)、等幅数字の2進数装飾。
- 暫定方向: ダーク基調(チャコール)+黄アクセント+ミントの補助光。ただし
  **確定は全資料受領後**。ライト寄り(紙面白基調)の可能性も第1弾内に存在する。

## 0-B. 参考資料メモ(第2弾・ゲーム内スクリーンショット5枚 / 2026-07-18受領)

- **明部(紙面ホワイト)の比重がかなり大きい**: 購入モーダル・Protocol Pass・
  誕生日ダイアログ・接続画面はいずれも白〜ライトグレー(#e5e5e8〜#eef0f2 前後)が主面。
  白紙面+黒文字+黄アクセントの「印刷物系ライトUI」が本作UIのもう一つの顔。
  → サイトテーマは**単一配色**のため、「チャコール基調」か「紙面ライト基調」かの
  二択になる。判断材料: 明部でも文字は黒、CTAは黄+黒文字で共通。
- **黄は明部でも唯一の主アクセント**(#f5e900〜#ffe600)。太い水平ルール線、
  キーワードの文字色強調(黄/橙)、CTAピル(等高線テクスチャ入り)に一貫使用。
- **状態色の体系**: 警告=サーモンピンク(#f8888a前後・白文字)/ 期限・開催情報=
  グリーンチップ(#2ed57a前後)/ 強調数字=オレンジ。赤は第1弾同様に記号的少量。
- **ボタンの対**: 確定=黄ピル+黒文字 / キャンセル=チャコールピル+白文字。
  どちらも内側に等高線(トポ)ラインの微テクスチャ。
- **ゴースト・タイポグラフィ**: 超大サイズの英字(PROTOCOL PASS / ENDFIELD)を
  地色+1段階差のグレーで背景に敷く。斜めハッチで面を埋める手法も継続。
- **明暗スプリット構図**: 協約通行証画面は上半分=白紙面(等高線)/下半分=
  黒床(光沢)の水平分割。黄のルール線が境界を横断する。

## 0-C. 参考資料メモ(第3弾・ゲーム内スクリーンショット5枚 / 2026-07-18受領)

※うち1枚(誕生日ダイアログ)は第2弾と同一カット。

- **オーバーレイの作法**: 画面全体を暗くディム→中央に白帯 or ダーク行リストを重ねる。
  見出しは白文字+下に短い斜めハッチの装飾下線(「新規追加」「スタンプを獲得しました」)。
  リスト行はチャコール地+左端に細い白エッジ、行間は極細の区切りのみ。
- **モノクロ処理画面**: 「情報分析中」はグレー単色のグラデ(上=暗/下=明)+
  白い極細枠のプログレスバー+斜めハッチ帯。彩色をほぼ使わない画面も存在する。
  → text-soft/faint 階調とライン色だけで成立する「無彩色の中間画面」がある点は、
  テーマの surface 階調設計(surface〜surface-3)の参考になる。
- **ショーケース(武器一覧)**: 白基調の縦パネルを斜めパース で並べ、アイテムは
  白地+ドットグリッドのカード。選択・NEW は黄〜金のアーク光+ダーク帯+プリズム
  フレアで強調。地面に超大の灰色ゴーストロゴ。→ 明部でも強調は黄系で一貫。
- **紫はごく稀な環境光**(音楽リストの背景、宝箱のホロ映像)としてのみ登場。
  UIの機能色ではない → テーマの vars には採らない(採るなら extra_vars の装飾まで)。
- **黄ピルのラベル**はモバイル通知でも「イベント」チップとして登場。黄+黒文字は
  画面サイズ・明暗を問わず共通言語。

## 0-D. 参考資料メモ(第4弾・ゲーム内スクリーンショット5枚 / 2026-07-18受領)

- **ランチャー画面(最重要色サンプル)**: 画面ほぼ全面が**ビビッドイエロー**。
  同心円のアーク模様+超大ゴーストロゴ「ENDFIELD」を地に敷き、中央に白フレームの
  ウィンドウ、左に黒ピル(ゲームを起動)と黄ピル(キャンペーンに参加)を縦置き。
  → 黄が「背景を占めるほどの主色」になり得ることを示す、最も強い黄基調の実例。
- **アーツユニット獲得(TYPE 42 / 四二式・粛陣)**: ライトグレー背景+黄の細ライン+
  **オレンジのアーク光**+黒帯白文字の銘板+黄「NEW」ラベル。機体色はティール(青緑)。
- **ゲーム内3D「建設基地」**: 実ワールドのトーン=くすんだグレー工業建築+白パネルに
  黄の記号+ハザードストライプ+自然の緑。UI外の世界観色は「無彩の工業+黄の標識」。
- **キャラ演出(暗)**: 暗い藍〜紫背景に**シアン/ティールのネオン**発光と白い紋章、
  CMYK(赤緑青)極細ストライプの差し色。シアンは第1弾スカウト画面と同じ環境光。
- **上級配給解放(色対比の教科書)**: 上段=**黄ブロック**(源石配給)/下段=
  **赤〜オレンジブロック**(協約特注)をグレー地に並置。報酬名に「テーマ・根源の痛み」
  「テーマ・…」「フィルター・…」= ゲーム内にも"テーマ"報酬概念がある(命名の参考)。
  → **黄=主/赤オレンジ=副(警告・特注)**の二色体制がここで最も明快に出る。

### 現時点(資料1〜4)の配色所見 ※確定は全資料受領後

- **主アクセント= ビビッドイエロー #f5e100〜#ffe600**(ほぼ確定)。`accent-contrast`
  は黒系(#1a1a1a前後)。明部・暗部・大面積いずれでも黄+黒文字が一貫。
- **副アクセント候補**: 赤〜オレンジ(#e8442e〜#ff5a2c。警告・特注の系統色)。
  テーマの単一 accent は黄にし、赤オレンジは extra_vars(glow/grad)か状態色に回す案。
- **補助環境光**: シアン/ティール(キャラ・スカウト・宝箱)。UI機能色ではないため
  vars 本体には入れず、装飾 extra_vars 止まりが妥当。
- **基調は二択のまま**: 「チャコール(#1a1a1a系)ダーク」か「紙面ホワイト(#eef0f2系)
  ライト」。作品はどちらも多用する。サイトの既存テーマは dark/light/g/suzaku が
  すべてダーク寄り運用のため、**endfield はダーク基調(チャコール+黄)を第一候補、
  ライト版は将来テーマとして分離**が現実的(単一テーマは1配色のため)。最終判断は
  残り資料+ユーザー意向で確定する。

## 1. collab-endfield.css 流用禁止の理由(重要)

`assets/css/collab-endfield.css` は **コラボ特設 LP 専用のスコープ付き CSS** であり、
サイト全体テーマとは責務が別。流用してはならない(ユーザー指示)。

- 変数体系が別物: LP は `--cl-*` 系のローカル変数で、テーマ機構の
  `--bg / --surface / --text / --accent` 等(THEME_VAR_KEYS の16変数)とは互換がない。
- スコープが別物: LP の配色は `.cl-endfield` 配下だけで完結する演出用。
  サイトテーマは `[data-theme=endfield]` で **全ページの基礎トークンを上書き**する。
- 要求水準が別物: LP は暗背景前提の演出色だが、サイトテーマは全ページの本文・表・
  フォームで WCAG AA(本文 4.5:1 目安)を満たす必要がある(H-9-2 の磨き直し基準)。

よって実装は **data_themes.py への独立定義**として行う。LP と世界観(白×黒×
ビビッドイエロー、工業ターミナル)は共有してよいが、色値は AA 基準で新規に起こす。

## 2. 実装手順(資料到着後)

テーマ機構は単一ソース化済みのため、**編集するのは原則 data_themes.py の 1 dict のみ**。

1. `scripts/data_themes.py` の endfield 項目に以下を実装:
   - `status` を `"planned"` → `"live"` に変更
   - `swatch`(選択 UI の色見本)/ `meta`(theme-color)/ `color_scheme` を追加
   - `vars` に THEME_VAR_KEYS の16変数をすべて定義(欠落は validate が検出)
   - 必要に応じて `extra_vars`(`grad-flame` / `glow-*` 等。g / suzaku の項目を参照)
   - `desc`(任意。ドロップダウンの説明文)
2. `python3 scripts/gen.py` を実行 — これだけで以下がすべて自動反映される:
   - `assets/css/themes.css` に `[data-theme=endfield]` ブロック生成
   - ヘッダードロップダウン / ドロワー / 設定ページ(`<!--THEME_SEG-->`)にボタン追加
   - 早期適用スクリプト(`window.SZ_THEMES`)と meta theme-color 同期に組み込み
   - interact.js の「endfield ボタン非存在」テストは **live 化に合わせて削除または
     「存在する」側へ書き換えること**(そのままだと FAIL する。意図的な設計)
3. 続報ニュースを `scripts/data_misc.py` の NEWS に追加
   (「サイトテーマ『前線』提供開始」。告知記事 `2026-07-endfield-site-theme` からの
   リンク導線も検討)。

## 3. 配色決定の観点(資料到着後に埋める)

- ベース: エンドフィールド工業の設計言語(白×黒のブロック反転+ビビッドイエロー)。
  ダーク基調かライト基調かは資料を見て決定する(LP は暗基調だが、テーマとしては
  「計器パネル風の明部が多い配色」もあり得る)。
- コントラスト実測(H-9-2 と同じ手順): `text / text-soft / text-faint` を bg・surface
  に対して実測し、本文 4.5:1 / 補助 4.5:1 目安・装飾 3:1 を確認してから確定する。
- `accent-contrast`: ビビッドイエローを accent にする場合、白文字は AA を満たさない
  可能性が高い。暗色(例: 装甲の黒)を検討する。
